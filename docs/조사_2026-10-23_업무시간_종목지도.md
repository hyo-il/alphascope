## 0. 잰 방법 (숫자를 읽기 전에)

- **업무 하나** = 지시서 하나(첫 줄에 「작업 지시서」 · 「# AlphaScope …」 가 있거나 1,500자 넘는 붙여넣기) + 그 뒤 「이어서 작업해주세요」 · 「계속」 · 「진행중인가요?」 같은 이어가기 메시지. 같은 지시서를 연달아 두 번 붙인 것은 하나로 셌다. 「푸시해주세요」 · 질문 같은 그 밖의 짧은 메시지는 「짧은 요청」 으로 따로 셌다.
- **끝** = 그 구간의 다음 사용자 메시지 전 마지막 답. 마지막 답에 「작업 완료」 · 「푸시 준비 완료」 가 있으면 표의 「끝 표시」 칸에 ○.
- **시간** = 구간(사용자 메시지 → 다음 사용자 메시지 전 마지막 답) 길이의 합 — 사용자를 기다린 빈 시간(밤사이 · 다음 지시 전)은 들어가지 않는다.
  - **멈춤 포함** = 그 합 그대로. **활동** = 멈춤 포함 − 아래 「멈춤」.
  - **멈춤** = ① 사용 한도(세션 · 주간 한도에 걸린 뒤 풀려 자동으로 이어질 때까지) ② 맥 잠자기 · 연결 끊김(「API Error: Your computer went to sleep」 · 「Connection lost」 직전 구간) ③ 30분 넘게 아무 사건도 없던 구간(원인 확인 못 함).
- **단계** = 사건(도구 호출 · 결과 · 알림 · 답) 사이 구간마다 정했다.
  - **대기**(명령이 도는 중) — 그 도구의 범주. **백그라운드 대기** — 다음 사건이 백그라운드 끝 알림이면 그 알림의 명령 범주. **모델**(생각 · 쓰기) — 그 구간 바로 뒤에 부른 도구의 범주(도구 없이 글만 쓰면 「보고 작성」).
  - 범주는 도구 이름과 명령 글자로 정했다(예: `design:check` → 디자인 점검, `tsc` → 타입 검사, `:test` → 시험, 바이트 비교 · `until` 기다리기는 따로). 몇 초짜리 읽기 명령이 3분 넘게 결과가 없던 것은 「권한 확인 대기 추정」 으로 따로 셌다(기록으로 확인 못 함).
  - 표에서는 묶어 보인다: 조사 · 구현 · 검사(타입 · 빌드 · 시험 · 바이트 비교) · 화면 확인(서버 · Playwright · 디자인 점검) · 검토 · 기다림 · 문서 · 보고(문서 · 커밋 · 보고 글) · 멈춤.
- **업무 크기** = 업무 시간 범위(시작 1분 전 ~ 끝 2분 뒤)에 만든 커밋의 바뀐 파일 수 · 바뀐 줄 수(`git log --numstat`). 작음 = 파일 1~3 · 보통 = 4~9 · 큼 = 10 이상 · 커밋 없음 = 0(조사 · 문서만 등).
- **토큰** = 메인은 응답(`message.id`)마다 한 번씩 `usage` 를 더했다. 서브에이전트는 하위 기록(`subagents/*.jsonl`)을 시각으로 업무에 붙였다.
- **다시 돈 것** = 실패로 끝난 타입 검사 · 빌드 · 시험 · 화면 확인 · 디자인 점검 호출 수(오류 표시 · `error TS` · 「N개 실패」 · `FAIL` · 0 아닌 끝 코드 기준). 실패 뒤 다시 돌렸는지까지 짝지어 보지는 않았다.

## 3. 확인 못 한 것과 이유

- **사용자가 처음 한 말(지시서를 쓰기 전)**: 지시서는 다른 대화에서 쓰여 붙여넣어졌다. 그 대화는 이 프로젝트의 Claude Code 기록이 아니라 열지 않았다. 그래서 첫 요청에 「정규장 밖」 이 들어 있었는지는 확인 못 했다(이 기록에서는 지시서 글자만 확인).
- **2026-09-18 이전 업무**: 이 폴더에 기록이 없다.
- **2026-10-06 이전 서브에이전트 토큰**: 하위 기록(`subagents/`)이 없다. 그 이전 업무의 서브 토큰은 0 으로 보인다.
- **30분 넘는 빈 구간 · 3분 넘게 결과가 없던 읽기 명령의 원인**: 맥 잠자기 · 권한 확인 창 · API 지연으로 짐작되지만 기록에 원인이 남지 않는다. 각각 「원인 확인 못 함」 · 「권한 확인 대기 추정」 으로 따로 셌다.
- **「검토 결함 고침」 단계**: 고친 편집이 검토 결과 때문인지 기록으로 가를 수 없다. 「구현」 에 합쳤다.
- **「다시 돈 것」**: 실패로 끝난 호출 수만 셌다. 같은 명령을 고친 뒤 다시 돌렸는지 짝짓지는 않았다. 시험 출력에 「FAIL」 이 섞인 정상 실행도 있을 수 있다.
- **업무 크기**: 커밋을 시각 범위로 업무에 붙였다. 사용자가 그 사이 직접 만든 커밋이나 업무 경계에 걸친 커밋은 섞일 수 있다.
- **규칙 문서 크기**: 지금 크기만 쟀다. 관리 루트는 git 밖이라 지난 크기는 없다.
- **33차 안에서 종목 지도(D)에 든 시간만**: 도구 호출을 절마다 가를 표시가 없어 재지 못했다.
- 숫자를 낸 분석 스크립트는 scratchpad 에만 두었고 저장소에는 넣지 않았다.
